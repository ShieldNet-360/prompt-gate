Technical Architecture

Prompt Gate is an open-source, privacy-first AI Data Leakage Prevention system for desktop environments. It intercepts requests bound for AI tools via DNS, browser extensions, or an optional MITM proxy, executing a high-performance in-memory DLP pipeline to prevent secret leakage.

Go Backend

agent/cmd/agent/main.go

Single statically compiled binary running on `127.0.0.1`. Includes an embedded DNS resolver, HTTP API, token-bucket rate limiter, and SQLite store for config/counters.

Electron Tray

electron/main.ts

System tray interface interacting with the Go backend via HTTP. Provides configuration UI for rules, policies, and MITM proxy management.

Browser Extension

extension/src/background/

Manifest V3 extension for Chrome/Firefox/Safari. Captures text from paste/submit events and forwards to backend via Native Messaging (or HTTP fallback).

Privacy & Data Flow

Core Invariant: Process, Don't Persist. At no point in the default flow is a domain name, URL, IP address, or request content written to any persistent storage.

Zero Payload Persistence: DLP scan content is processed strictly in-memory and garbage-collected immediately after the response is sent. Counters (`dns_blocks_total`, `dlp_blocks_total`) are stored as bare integers in SQLite.

Layered DLP Pipeline

To meet a strict < 1ms execution budget, Prompt Gate avoids running heavy regexes universally. Instead, it utilizes an advanced, adversary-resistant layered pipeline.

Core Component Technical Details

MITM Proxy (Optional Tier 2)

Located in agent/internal/proxy/. Built on `goproxy` running at `127.0.0.1:8443`.

  • Generates per-device Root CA (ECDSA P-256) on first run, cached in `~/.prompt-gate/ca.crt`.
  • Leaves non-Tier-2 traffic as opaque TCP tunnels. Decrypts only traffic bound for inspected domains.
  • Fires HTTP 451 upon DLP block, dropping the request body from memory instantly.

SQLite Store

Located in agent/internal/store/. Utilizes pure Go SQLite (`modernc.org/sqlite`) running in WAL mode.

  • Database stays extremely small (~8KB default).
  • Contains tables: `category_policies`, `aggregate_stats`, `dlp_config`, `dlp_allowlist` (salted SHA-256 hashes only).
  • The `block_events` table explicitly requires opt-in via `agent_preferences`. Checked universally on write-paths.

File Upload & Payload Inspection

Prompt Gate inspects file uploads traversing through the MITM Proxy (and text from the browser network interceptor), focusing exclusively on surfacing embedded text to the DLP Pipeline.

Transparent Decompression

agent/internal/proxy/extract.go

Transparently inflates gzip and deflate body encodings so the DLP scanner can view the raw plaintext. A strict byte boundary is applied to prevent decompression bombs.

Multipart Parsing

Parses multipart/form-data bodies (e.g., Anthropic/OpenAI Files API). It extracts not just the text content of every part, but also filenames, which frequently embed secrets (like .env or id_rsa).

Base64 Extraction

Hunts for Base64 blobs embedded inside JSON arrays, octet-stream uploads, or raw strings. If a matched blob decodes to overwhelmingly printable characters (valid UTF-8 text), it is appended to the scan buffer.

What it Checks: 165 real-world detection patterns across 14 categories. This includes: Cloud Provider Keys (AWS, Azure, GCP), Infrastructure (Terraform, K8s, Docker), Code hosts (GitHub, GitLab), AI/ML API Keys, Payment Processors (Stripe), CI/CD Tokens, Messaging (Slack, Twilio), Auth/Identity (Auth0, Okta), Language Ecosystems (NPM, PyPI, Maven), Mobile (iOS APNs, Android Signing), Database credentials, PEM/Private Keys, JWTs, generic passwords, and PII (SSN, credit cards).
Scope limits: Binary document formats (PDFs, zip, Office files) and non-textual image blobs are intentionally bypassed to strictly bound the scan time and memory footprint (maxScanBytes limit).
